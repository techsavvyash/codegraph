## Generation Core — `generateAndVerify`

The central generation function used by all documentation generators. It coordinates LLM generation with evidence verification.

```mermaid
graph TD
    subgraph Callers
        C1[GeneratePRSummaryForScope]
        C2[GenerateFlowSummariesForScope]
        C3[GenerateDocstringSuggestionsForScope]
    end

    subgraph "Orchestration Layer"
        C1 --> R[Run — stages.go]
        C2 --> R
        C3 --> R
    end

    R -->|dispatches| GAV[generateAndVerify]

    subgraph "Storage"
        GAV --> SPR[StorePRSummary]
        GAV --> SFS[StoreFlowSummary]
        GAV --> SDS[StoreDocstringSuggestion]
        SPR --> MCP2[marshalCitationProps]
        SFS --> MCP2
        SDS --> MCP2
    end

    subgraph "Verification"
        GAV --> EVR[ensureVerificationResult]
        GAV --> NV[normalizeViolations]
    end

    subgraph "Error Handling"
        GAV --> GVE[generationViolationsFromError]
        GVE --> IEV[insufficientEvidenceViolation]
        GVE --> LIV[lowInformationViolation]
        GAV --> SD[storeDiagnostic]
        GAV --> SGFD[storeGenerationFailureDiagnostic]
    end
```

### Key observations

- **9 callers** (3 generators + 6 test functions) — this is the single most-called internal function
- **8 callees** — stores results, verifies output, handles errors
- All three generation scopes (`PR`, `Flow`, `Docstring`) converge through this function
- `Run()` in stages.go orchestrates the generation pipeline and dispatches to all three generators
