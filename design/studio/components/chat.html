Why does budget exhaustion never stamp chunks?
3 tool calls

codegraph_expandmatchChunks() · MENTIONS in180ms

Budget exhaustion short-circuits before stamping is ever reached. Each judge call reserves budget through 2spendBudget(), and when the reservation fails, 1matchChunks() returns with stampAllowed=false so the run stays resumable:

if !r.budget.spendBudget(cost) { return ErrBudgetExhausted // chunk left unstamped }

That behavior is specified in 3RFC-011 › Budget — exhausted runs must leave chunks unstamped so the next run retries them instead of treating them as matched.
